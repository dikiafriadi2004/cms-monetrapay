## landing-page.blade.php

**One potential variable name inconsistency, no invisible elements.**

- Div tag balance: All matched.
- Blade directives: All `@if` / `@foreach` / `@php` / `@endphp` properly closed. The `@php ... @endphp` block in the hero for `$heroTitle` manipulation is correct.
- Button/link visibility:
  - Nav CTA: `bg-yellow-400 text-black` — good contrast.
  - Hero CTA: `bg-yellow-400 text-black` — good contrast.
  - CTA section: `bg-black text-yellow-400` on `bg-yellow-400` — good contrast.
  - All link text on black bg uses `text-white`, `text-yellow-400`, `text-gray-400`, `text-gray-500` — all visible.
- **Bug found**: Footer uses `$siteSettings['site_name']` and `$siteSettings['site_description']`, while the navbar of the same file also uses `$siteSettings[...]`. Other themes use `$siteName` directly. If the controller passes `$siteName` but not `$siteSettings`, the footer/nav site name would silently fall back to `config('app.name')`. This may cause a visual mismatch if the admin-configured site name differs. Not an HTML crash bug but a potential data display inconsistency.
- **Bug found**: Blog section uses `$blog->excerpt ?? Str::limit(strip_tags($blog->content ?? ''), 120)` — if `$blog->content` is null, `strip_tags(null)` works in PHP 8 but `$blog->content ?? ''` makes it safe. Minor, no visual bug.
- No gradient classes.

**Bugs:**
- Bug 1: ~line 5 (nav) and ~line 170 (footer) — `$siteSettings['site_name']` used instead of `$siteName` variable. If `$siteSettings` array is not passed by the controller, this will throw an undefined variable error in strict mode or show blank. Fix: Use `$siteName ?? config('app.name')` consistently, or confirm `$siteSettings` is injected by the controller.

## navbar.blade.php (partials)

**One bug found.**

- Div/tag balance: `<header>` opened, closed ✓. All `<div>`, `<nav>`, `<button>` tags balanced.
- Blade directives: `@foreach($primaryMenu as $item)` → `@endforeach` ✓ (twice, desktop + mobile). `@if(!empty($ctaText))` → `@endif` ✓ (twice). `@if(!empty($primaryMenu))` → `@endif` ✓. `@if(file_exists(...))` → `@else` → `@endif` ✓.
- **Bug found**: Line ~56 — `ltrim(parse_url(...) ?? '/', '/')` — the `ltrim` call uses only 2 arguments (string, characters) which is correct. However the mobile nav repeats this on line ~100+ as a one-liner: `$p = ltrim(parse_url($item['url'] ?? '/', PHP_URL_PATH) ?? '/', '/');` — this is fine (2 arguments). This code is safe in PHP 8.
- Button/link visibility: All text on white background uses `text-slate-600`, `text-primary`, `text-white` — all visible.
- Dark mode toggle: `x-data`, `x-show` Alpine.js directives — no missing `x-cloak` concerns.
- **Potential bug**: `h-15` class used (`class="... h-15 lg:h-16"`) — Tailwind does not have `h-15` by default (only `h-14`, `h-16`). This is a non-standard Tailwind class. The element will have no height constraint applied on mobile, relying on content height. Not invisible but may cause layout shift.

**Bugs:**
- Bug 1: ~line 8 (`<div class="flex items-center justify-between h-15 lg:h-16">`) — `h-15` is not a standard Tailwind CSS utility. The navbar inner div will have no explicit height on mobile/small screens. Fix: Change `h-15` to `h-14` or `h-16` to match the `lg:h-16` target.

- `dark-mode-elegant.blade.php` — copyright text `text-gray-700` on near-black `bg-[#050505]` is nearly invisible (~2.5:1 contrast ratio).

- `creative-agency.blade.php` — copyright `text-gray-600` on dark footer background.
- `portfolio-showcase.blade.php` — service card 4 description `text-white/75` on gold background.

**Non-standard Tailwind class:**
- `navbar.blade.php` — `h-15` does not exist in standard Tailwind; height will be ignored on mobile.
